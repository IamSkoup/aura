# AURA WEAR — инструкция по запуску магазина

Сайт состоит из каталога одежды и аксессуаров, конструктора принтов с 3D-просмотром, коллекции готовых дизайнов, личного кабинета, корзины, заказов и панели управления.

## 1. Запуск

На компьютере или сервере нужен Node.js версии 20 или новее.

1. Установите зависимости: `npm ci`.
2. Скопируйте `.env.example` в `.env.local`.
3. Укажите в `.env.local` данные своего проекта Firebase и хранилища файлов.
4. Для работы на компьютере запустите `npm run dev`.
5. Для публикации выполните `npm run build` и `npm run start` либо подключите репозиторий к Firebase App Hosting.

Проверка: `npm run typecheck`, `npm run lint`, `npm test`.

## 2. Аккаунты и хранение макетов

В Firebase откройте Authentication и включите вход по Email/Password. Создайте Realtime Database, укажите адрес базы и публичные настройки приложения. Серверу нужен доступ Firebase Admin через учётную запись сервиса (не кладите ключ в исходный код).

Для загрузки изображений и сохранения производственных макетов подключите приватное Firebase Storage или S3-совместимое хранилище. Укажите соответствующие переменные окружения. Исходники покупателей не должны быть публичными.

Настройте правила доступа из `database.rules.json`, создайте доверенного администратора командой `npm run grant-admin -- email@example.com` после настройки доступа на сервере. Управление товарами, отзывами и заказами находится в разделе `/admin`.

## 3. Каталог и товары

В поставке есть 12 стартовых карточек: футболки, худи, свитшоты, кружки, чехлы и постеры. Пока база данных пустая, они отображаются в каталоге для оформления витрины.

Чтобы перенести карточки в собственную базу, выполните `npm run seed:catalog` после настройки Firebase. Команда добавляет только отсутствующие товары и не перезаписывает отредактированные.

**До начала продаж:** замените иллюстрации настоящими фотографиями товара, проверьте цены, остатки, замеры, состав, плотность ткани и перечень моделей телефонов. Размерная сетка на сайте ориентировочная; укажите фактические данные поставщика.

Готовые тематические принты в галерее можно сразу открыть в конструкторе и изменить. Для публикации собственных изображений используйте раздел готовых шаблонов в `/admin` и загружайте только материалы с правами на коммерческое использование.

Отзывы и фотографии покупателей появляются после настоящих покупок и модерации: вымышленные отзывы в сайт не добавлены.

## 4. ЮKassa — подключение платежей

Серверная интеграция ЮKassa уже предусмотрена. До подключения система не принимает оплату и сообщает об этом посетителю после нажатия кнопки оформления заказа.

1. Получите Shop ID и секретный ключ в ЮKassa, настройте чеки и согласуйте условия договора.
2. На сервере установите `PAYMENT_PROVIDER=yookassa`, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `NEXT_PUBLIC_SITE_URL=https://ваш-домен`.
3. В настройках уведомлений ЮKassa укажите адрес `https://ваш-домен/api/payments/webhook` для `payment.succeeded` и `payment.canceled`.
4. Согласуйте налоговую настройку и состав электронного чека с платёжным провайдером и бухгалтером.
5. Опубликуйте корректные контакты, реквизиты, политику обработки персональных данных, оферту и правила возврата. Заполните поля `settings/public` в Realtime Database; флаги `legalReady` и `merchantReady` включайте только после проверки информации.
6. Проверьте полный цикл: заказ → страница оплаты → webhook → статус «Оплачен» → макет в админке. Затем проведите отдельную проверку на рабочем магазине.

Ключи платёжной системы должны храниться только на сервере. Ни в GitHub, ни в клиентском коде их быть не должно.

## 5. Работа с заказами

Покупатель создаёт макет и добавляет его в корзину. После оплаты заказ появляется в панели управления. Через `/admin/orders` можно проверить заказ, обновить его статус и скачать файл принта для производства.

Стоимость и сроки доставки, фактический список производимых товаров, поддерживаемые модели чехлов и правила возврата уточняются владельцем магазина до запуска.

## 6. Дизайн

Светлая и тёмная темы переключаются в шапке сайта. При первом входе тема определяется по настройке устройства, выбранная вручную сохраняется.

Изображения фонов лежат в `public/images`: `hero-light.webp`, `hero-dark.webp`, `editorial-flatlay.webp`. Модель футболки находится в `public/models`. Цвета интерфейса и адаптивные стили — в `src/app/aura-theme.css`.
