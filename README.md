# Aura Wear

Сайт: [iamskoup.github.io/aura](https://iamskoup.github.io/aura/). Публикация выполняется автоматически из ветки `main` через GitHub Actions. Это статическая версия: для её работы не нужен Next.js, сервер, платный тариф Firebase или банковская карта.

## Инструкция для владельца Aura Wear

### Что доступно сейчас

Каталог содержит шесть образцов с **примерными, не подтверждёнными владельцем ценами**: футболка 1 990 ₽, худи 3 990 ₽, свитшот 3 490 ₽, кружка 790 ₽, чехол 990 ₽, постер 890 ₽. Конструктор футболки позволяет менять цвет и размер, загружать изображения, добавлять надписи, рисовать кистью, двигать и поворачивать слои, смотреть изделие в 3D и сохранять проекты в браузере. Готовые оригинальные принты открываются в конструкторе и допускают редактирование. Корзина сохраняется в браузере. Страница оформления показывает состав заказа и поля доставки, но **платёж не создаётся, заказ не отправляется, деньги не списываются**: после нажатия кнопки оплаты появляется сообщение с ссылкой на эту инструкцию. Введённые на странице оформления данные никуда не отправляются. Очистка данных браузера удалит сохранённые проекты.

Присланная серверная версия сохранена в ветке [`uploaded-next`](https://github.com/IamSkoup/aura/tree/uploaded-next). Более ранняя серверная версия находится в [`server-archive`](https://github.com/IamSkoup/aura/tree/server-archive).

### Как открыть и обновлять сайт

1. Откройте [Settings → Pages](https://github.com/IamSkoup/aura/settings/pages) и выберите **Build and deployment → Source: GitHub Actions**. Первый запуск может потребовать подтверждения GitHub Pages в настройках репозитория.
2. После каждого обновления `main` дождитесь зелёного результата в [Actions](https://github.com/IamSkoup/aura/actions/workflows/pages.yml).
3. Откройте [публичный сайт](https://iamskoup.github.io/aura/). Иногда новая версия появляется спустя несколько минут.

Для запуска на своём компьютере установите Node.js 22, выполните `npm ci`, затем `npm run dev`. Команда `npm run build` создаёт готовые файлы в `dist-pages`. Проверки: `npm run typecheck` и `npm test`.

### Firebase на бесплатном тарифе Spark

Публичные настройки веб-приложения указаны в `static-site/firebase.ts`. В консоли Firebase откройте **Authentication → Sign-in method** и включите Email/Password. В **Authentication → Settings → Authorized domains** добавьте `iamskoup.github.io`. Для чтения опубликованных товаров из Realtime Database примените правила из `database.rules.json` в разделе **Realtime Database → Rules**. Не добавляйте сервисный ключ Firebase Admin в репозиторий: он не нужен статическому сайту.

### Каталог и реальные товары

Образцы описаны в `static-site/catalog.ts`, изображения — в `public/images`. **Замените примерные цены реальными**, когда владелец предоставит прайс. Для открытия продаж также нужны фотографии с правами использования, SKU, остатки, цвета, размеры, состав, фактическая таблица размеров и размеры печатных зон. Публикуйте проверенные данные в Realtime Database в узле `products`; карточки с `published: true` будут показаны рядом с образцами. Чтобы заменить образец, удалите его из локального массива `demoProducts` или назначьте опубликованному товару тот же `id`. Публичные изображения размещайте по HTTPS либо в `public/images`. Не публикуйте исходники покупателей в Realtime Database.

Оригинальные эскизы из раздела «Готовые дизайны» находятся в `static-site/print-catalog.ts`. Категории можно расширять, соблюдая права на иллюстрации и названия. Студийные изображения в `public/images` созданы для оформления сайта и не являются фотографиями покупателей.

### Размеры, материалы и отзывы

Разделы размеров и материалов читают проверенные сведения из `settings/public` в Realtime Database. Для каждого изделия нужна отдельная размерная сетка от поставщика. Формат данных:

~~~json
{
  "sizeCharts": [
    {"productName": "Название изделия", "rows": [
      {"size": "M", "widthCm": null, "lengthCm": null, "chestCm": null, "sleeveCm": null}
    ]}
  ],
  "materials": [
    {"name": "Название материала", "composition": "Состав по документу поставщика", "densityGsm": null, "care": "Инструкция по уходу"}
  ]
}
~~~

Значения `null` обозначают незаполненные места для фактических замеров и плотности — не публикуйте их как характеристики товара. Пока данные не внесены, посетитель видит пояснение без выдуманных размеров и состава.

Отзывы читаются из узла `reviews` только при `published: true` и `verifiedPurchase: true`. Фотографии появляются в галерее только при `photoConsent: true` и публичном HTTPS-адресе. Владелец должен подтвердить покупку, получить согласие на публикацию и провести модерацию перед добавлением записи. Три текста, предоставленные для оформления, находятся в `static-site/SampleReviews.tsx`; их происхождение и согласие авторов пока не подтверждены, поэтому они отдельно обозначены как образцы. Портреты `review-portrait-*.webp` созданы для макета и **не изображают названных людей**. После получения доказательств публикации и согласий можно перенести подлинные отзывы в Firebase; изображения авторов заменять только их настоящими фото с разрешением.

### 3D-футболка и новые модели

Модель хранится в `public/models/aura-tee.glb`. Её исходный скрипт — `tools/generate-shirt.py`; для повторной сборки нужен Blender 4.3 или новее: `blender -b -noaudio --python tools/generate-shirt.py`. Перед заменой другой моделью сохраните UV-развёртки и имена поверхностей `Front_Print_Surface` и `Back_Print_Surface`, иначе принт не попадёт на ткань. У новых изделий должны быть собственные подготовленные модели и печатные зоны. 2D-образцы других товаров не выдаются за готовый 3D-просмотр.

### Как подключить ЮKassa и настоящие заказы

GitHub Pages не может безопасно принимать оплату: секретный ключ ЮKassa и проверка уведомлений должны работать на сервере. Начните с ветки `uploaded-next` на серверном хостинге. Владелец магазина должен получить договор, Shop ID и секретный ключ ЮKassa, предоставить реквизиты, данные для чеков и необходимые правовые документы. Укажите секреты в настройках серверного хостинга, настройте адрес уведомлений `/api/payments/webhook` и проверьте создание платежа, проверенное уведомление, повторные webhook-события, отмену и возврат. Только сервер должен вычислять цену и создавать заказ. На статическом сайте кнопка «Перейти к оплате» показывает ошибку о неподключённом сервисе и ссылку на этот раздел. Для настоящих заказов замените этот обработчик на вызов защищённого API, который после проверки состава корзины, цены и доставки создаст заказ и платёж, вернёт адрес оплаты, а статус заказа обновит только после проверенного уведомления. Не переносите секретный ключ в браузер.

### Файлы, доставка и производство

Для оригинальных фото и макетов печати потребуется приватное файловое хранилище с серверной загрузкой. Подойдут Firebase Storage при доступном тарифе или S3-совместимый сервис; стоимость зависит от провайдера. Настройте проверку формата, размера и прав доступа. Для доставки заключите договор с перевозчиком или задайте собственные тарифы, сроки, города и способы выдачи; расчёт и подтверждение заказа должны выполняться на сервере. Прежде чем принимать заказы, согласуйте требования типографии к физическому размеру печати и DPI. Браузерный 3D-просмотр не является производственным файлом.

### Что может потребовать оплаты

Публикация этого сайта на GitHub Pages и базовое использование Firebase Spark могут быть бесплатными в пределах лимитов. Для коммерческого запуска могут потребовать оплаты серверный хостинг, объектное хранилище, домен, платёжные комиссии, онлайн-касса, доставка и превышение лимитов Firebase. Не подключайте платные сервисы без согласования с владельцем бизнеса.
